# 核心发现：项目指纹陷阱 —— 兼测试充分性指标效度的正确评估方式

**日期**：2026-10-15 起，2026-10-16 更新　**产出**：ClawsGO Science Agent
**数据**：219 个测试子集实例 / 70 个独立缺陷版本 / **7 个 Defects4J 项目**
**脚本**：`scripts/analyze_fixed_effects.py`、`scripts/analyze_rq3.py`、`scripts/collect_subsets.py`

---

## 摘要

在 Defects4J 上用**人工构造的测试子集**测量覆盖率、变异分数与断言层面的行为匹配特征，并以"该套件能检出本项目多少个真实缺陷"为结果变量，我们得到三个结论：

1. **套件规模支配一切**。控制规模与项目身份后，只有覆盖率仍携带额外的解释力；变异分数与行为匹配特征都不显著。
2. **断言层面的"行为匹配"特征是项目指纹**。仅凭这些特征就能以 **86.3%** 的准确率识别实例属于哪个项目（随机基线 14.3%）。这使它们在任何未控制项目身份的汇总分析中都会"预测"缺陷检测能力。
3. **一个看似强健的效应是假象**。"强断言占比越高、缺陷检出越少"在跨项目下显著（ρ=−0.254, p=0.033），在项目内消失（ρ=−0.210, p=0.081），在更严格控制下完全不显著。

**方法学含义**：该领域的指标效度研究若在少数项目上反复抽样、且不控制项目固定效应，会系统性地得出错误结论。本文给出可复用的诊断与协议。

## 一、实验设计

| 要素 | 设计 |
|---|---|
| 被测对象 | 测试套件子集（人工构造，规模比例 0.1 / 0.25） |
| 结果变量 | 缺陷检出率 = 该子集能检出本项目多少个真实缺陷 / 项目缺陷总数 |
| 结果变量的计算 | 依据各缺陷的触发测试元数据，**无需执行测试** |
| 规模控制项 | log(实际运行的测试类数) |
| 项目控制项 | 项目虚拟变量（固定效应） |
| 标准误 | 按缺陷版本聚类 |

**构造测试子集的方法**（本项目的工程基础）：Defects4J 的 `coverage`/`mutation` 都不接受测试清单，`all_tests` 会被框架重写。但项目构建文件里的 fileset 是对**测试源码目录**的筛选，因此把不参与子集的测试源码移出测试目录，框架就只运行子集。实测：Lang-11b 保留 10% 后覆盖率 94.5%→20.6%，耗时 134s→23s。

依赖问题由**自适应修复**兜底：编译失败时解析 javac 报的缺失符号，从暂存区补回源文件，循环至编译通过。

## 二、结论与证据

### 2.1 项目身份是最强的混淆源

| 特征集 | 预测项目的 5 折交叉验证准确率 |
|---|---|
| 仅行为匹配特征 | **0.863** |
| 仅传统指标（规模+覆盖率+变异分数） | 0.795 |
| 全部特征 | 0.923 |
| 随机基线 | 0.143 |

**任何具有项目级风格的指标都会"预测"检出率，因为它首先在识别项目。**

### 2.2 交叉验证 R²：不控制项目会得出错误的模型排序

| 模型 | CV R²（无项目固定效应） | CV R²（含项目固定效应） |
|---|---|---|
| 仅规模 | 0.237 | 0.567 |
| **规模 + 覆盖率 + 变异分数** | 0.417 | **0.618**（最优） |
| 规模 + 行为匹配 | 0.262 | 0.553 |
| 完整 | **0.435**（看似最优） | 0.603（反而下降） |

- 无项目控制时，"完整"模型看起来最好（0.435），会诱导出"行为匹配有增量价值"的结论。
- 含项目控制时，**经典指标组合最优（0.618）**，加入行为匹配特征反而降到 0.603。

### 2.3 固定效应回归：只剩规模与覆盖率

| 模型（含项目虚拟变量，按缺陷版本聚类稳健标准误） | R² | 显著特征 |
|---|---|---|
| 仅规模 | 0.623 | `log_size` |
| 规模 + 覆盖率 + 变异分数 | 0.657 | `log_size`, **`coverage`** |
| 规模 + 行为匹配 | 0.632 | `log_size` |
| 完整 | 0.660 | `coverage` |

### 2.4 项目内相关：行为匹配特征的效应消失

| 特征 | 整体 ρ | 项目内 ρ | p |
|---|---|---|---|
| 套件规模 | +0.575 | **+0.728** | <0.001 |
| 覆盖率 | +0.609 | **+0.725** | <0.001 |
| 变异分数 | +0.069 | +0.295 | <0.001 |
| 每方法断言数 | −0.003 | +0.034 | 0.620 |
| **强断言占比** | −0.239 | **−0.075** | **0.266** |
| 谓词型断言占比 | +0.136 | +0.143 | 0.034 |
| 断言涉及调用数 | −0.049 | −0.173 | 0.010 |

版本级（n=70）：覆盖率项目内 ρ=+0.425（p<0.001），强断言占比项目内 ρ=−0.210（p=0.081，不显著）。

## 三、对本项目研究方向的含义

### 3.1 RQ3 的当前答案是"否"，但只针对语法层代理

本次实现的行为匹配特征是**语法层**的：断言类型占比、断言密度、谓词比例。它们：
- 与检出率在项目内无稳定关系；
- 主要是项目指纹；
- 加入模型后不带来增量，甚至损害样本外预测。

**这不等于原始假设被证伪。** 项目原本要研究的"行为匹配"是**语义层**的——测试验证的是程序**应该**做的行为（对照外部规范），还是实现碰巧的行为。二者是不同的量。本次结果的价值在于：**它证明语法层代理走不通**，为采用规范锚定的语义层测量提供了实证依据。

### 3.2 论文贡献的重排建议

| 优先级 | 贡献 | 证据状态 |
|---|---|---|
| **一** | **指标效度研究中的两个系统性陷阱（伪重复 + 项目指纹）及正确的评估协议** | 已有充分数据 |
| 二 | 现有指标的效度边界：规模支配、覆盖率有限独立贡献、变异分数贡献弱 | 已有充分数据 |
| 三 | 语义层行为匹配的增量预测力 | **尚未实现，结果未知** |

第一项成为论文主干，因为它不依赖任何尚未完成的工作，且结论对所有做此类研究的人都有约束力。

## 四、限制

1. **单一基准**：全部结论限于 Defects4J（7 个项目入选分析）。外部基准未做。
2. **检出率依赖触发测试元数据**，继承 Clean Program Assumption——触发测试失败不等于验证了预期行为。
3. **固定效应的固有代价**：若某特征的真实效应恰好在项目层面（如"某类项目的套件普遍更强"），固定效应会把它一并消除。这不是缺陷，但必须在论文中说明该结论的适用范围是**项目内**。
4. **变异分数限于配对抽样类集**（每项目 15 个类），全项目变异成本不可承受（实测 >21 分钟/版本）。
5. **行为匹配特征为语法层代理**，非语义层测量。
6. **覆盖率需插桩全部主类**，是采集成本的主要来源（Math 有 751 个主类，单实例覆盖率可达 900 秒以上）。
